# #2216 Lemmy Posts From the Feed — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Lemmy post renders from its feed item, never from article extraction, shows the link it shares as a link card, and loads its discussion — through a general "discussion thread" ruleset any later source reuses.

**Architecture:** A *discussion thread* is an entry the feed carries in full: its `url` is null and its `Discussion` names the post page. Three generic rules hang off that one shape: (R1) no article extraction, (R2) the links its body shows as their own address are shares that get link cards through the existing queue, (R3) its comments load automatically when a `CommentsSourceInterface` serves it. A source joins by adding one `PlatformEntryRuleInterface` rule (and, if its comments are not a feed, one comments source). Reddit already is one; Lemmy becomes the second.

**Tech Stack:** Symfony 8.1 / PHP 8.5 / Doctrine, PHPUnit 12, `league/commonmark` (new).

**Spec:** [#2216](https://github.com/larspohlmann/simple-feed-reader/issues/2216) and this plan's Decisions section (agreed in chat 2026-11-14: render from the feed, link card via the link-card queue, keep it simple and general).

## Decisions

1. **R1 needs no code.** `EntryArticleReader::pageUrl()` already returns null for a url-less entry, so the reader shows the feed body. The rule is documented, not re-implemented.
2. **R2 lives in `EntryShareClassifier`.** A discussion thread is classified from its body like a title-derived post, with two differences: no `OWN_PROSE_MAX` limit (a Lemmy link post often quotes the article at length, and the user wants the card) and never `ShareKind::Media` (Reddit thumbnails must not turn Reddit threads into media blocks). The bare `<a href="X">X</a>` stays in the body, as on every other post with a card; no trailing-URL trimming.
3. **R3 needs `Discussion` to keep `CommentsLoad::Auto` without a comments feed.** `Discussion::of()` keeps the load unless the feed is null *and* the load is `Manual`; a new `Discussion::platformThread(string $pageUrl)` builds `(pageUrl, null, Auto)`. RSS `<comments>` pages (`Manual`, no feed) stay load-less as today.
4. **Lemmy is recognised from the post, not the feed:** a `/post/<id>` URL plus the `submitted by <a …/u/…>name</a> to <a …/c/…>community</a><br>N points | <a>N comments</a>` header Lemmy writes into every item. Works on every instance; no `FeedPlatform` case.
5. **The header leaves the body; the author becomes the username** (`author` = link text, `authorUrl` = profile URL). The feed's `dc:creator` URL is no longer the displayed name.
6. **Comments come from the instance's public API**, `https://<host>/api/v3/comment/list?post_id=<id>&sort=Hot&type_=All&max_depth=8&limit=50`, no auth. The flat answer is threaded by `comment.path` (`0.<a>.<b>` → depth = segments − 2), depth-first, siblings in answer order. Deleted or removed comments drop; their replies keep their place one level up, as `SubstackThread` does.
7. **Comment bodies are Markdown** → `league/commonmark` (`html_input: escape`, `allow_unsafe_links: false`), then `EntrySanitizer`, as `CommentsFeedSource` sanitizes.
8. **No backfill.** Lemmy entries already stored keep their shape (unreleased data, nothing to migrate).

## Review Focus

1. **A Reddit thread must not change share kind.** Reddit bodies link `[link]`/`[comments]` (text ≠ address) and carry thumbnails → still `null`. Pinned in Task 2.
2. **A Lemmy text post (no shared link) gets no share and no card**, only its body. Pinned in Task 2 and Task 3.
3. **A post with a negative score or `1 comments`/`1 comment`** must still lose its header. Pinned in Task 3.
4. **A remote author** (`https://feddit.org/u/name` on a lemmy.world feed) keeps its own profile URL and name. Pinned in Task 3.
5. **A comment answer with a reply whose parent was removed** keeps the reply. Pinned in Task 4.
