# Rerankers Through the Rerank Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a connection use any reranker OpenRouter lists (`cohere/rerank-4-fast`, `voyageai/rerank-3`, `qwen/qwen3-reranker-8b`, …) as a scoring model: the catalog tags `["rerank"]` models, `RerankProtocol` asks `POST {base}/rerank` with the reader as the query and one line per article as a document, maps each result back by its `index`, and the picker tags the model "Reranker" and says what its score means.

**Architecture:** `ScoringProtocol::Rerank` (`'rerank'`, family `reranker`) gets `RerankProtocol` beside `SystemOneProtocol` in `ScoringProtocol/`: it budgets with `ScoringBudgetModel::forWindow($window, 100)`, packs the pool in chunks of 100 (the window bounds each document, not their sum), words each request through `Factory/RerankRequestFactory` (query from `Factory/RerankQueryFactory`, documents from `ScoringArticle::line()`), and sends through `RerankClient/HttpRerankClient` on the shared `ScoringHttpTransport`. The transport now hands each reply's decoder its request's position, so `Support/RerankReplyDecoder` can map `results[].index` to that request's entry ids. Everything after the reply (the `[0,1]` check, ×1000, the run-wide ranking, the finaliser, the feed) is the System One path unchanged. `TickPhases` gets a second message for a scoring-model switch, and the SPA's picker tags rerankers and explains each offered family's score.

**Tech Stack:** PHP 8.4, Symfony 7.4 (`AsTaggedItem`, `AutowireLocator`), PHPUnit 12, PHPStan level max with the custom rules in `backend/tests/PhpStan/`, PHPMD, phptramp, Infection; Angular 20 (signals, standalone components), Transloco, Jest (in the Docker frontend container), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-05-scoring-model-providers-design.md` (umbrella #1394), "Delivery" item 3 — this PR is sub-issue #1397. Read the spec's D2, D5, D6, D7, D8, D9, D10 and the spike findings first. The merged plans `docs/superpowers/plans/2026-10-05-1395-scoring-protocol-seam.md` (PR 1, D1–D21) and `docs/superpowers/plans/2026-10-05-1396-decision-models-picker.md` (PR 2, D1–D20) are settled; this plan builds on them. ## Global Constraints

The hint under the kind control explains, for each family the provider lists, what its score means. A run whose connection switched to another kind or protocol fails with a message naming the kinds; one whose connection switched scoring model fails with its own message. ## Decisions (judgement calls the spec did not settle, or where the code contradicted it, with the reason)

- **D1 — Every listed reranker has a window; no rule is invented.** Carry-forward (PR 2): a scoring descriptor needs a positive window (`ModelDescriptor` throws). OpenRouter's public `GET /api/v1/models?output_modalities=all` read on 2026-10-06 lists nine `["rerank"]` models, every one with a positive `context_length`: `cohere/rerank-4-pro` and `cohere/rerank-4-fast` 32,768, `cohere/rerank-v3.5` 4,096, `voyageai/rerank-3`, `rerank-3-lite`, `rerank-2.5`, `rerank-2.5-lite` 32,000, `qwen/qwen3-reranker-8b` 40,960, `nvidia/llama-nemotron-rerank-vl-1b-v2:free` 10,240. None lists `rerank` beside another output. The catalog's existing rule applies unchanged: `["rerank"]` with a positive window is `Scoring`/`Rerank`; without one it is left out.
- **D2 — Rerank retries 429 and 529.** Contradicts spec D6 ("`Rerank`: 429"). OpenRouter's OpenAPI for `POST /rerank` (docs page "Submit a rerank request", read 2026-10-06) documents `529 Provider Overloaded` beside `429`; the transport would otherwise read a 529 as unreachable and strike the run.
- **D3 — The transport hands the decoder the request's position.** Spec D7 maps `results[].index` back to articles but the code has nowhere to do it: `ScoringEndpoint`'s decoder is one closure for the whole wave and sees only the body and the response. `ResponseWave::positionOf()` names the response's request, and `ScoringEndpoint::decode()` passes it as a third argument; `HttpRerankClient`'s closure looks up that request's entry ids. System One's decoder keeps its two parameters (a closure may take fewer than the type names, as `ScoringHttpTransportTest`'s zero-parameter decoders already do). Rejected: an index-keyed intermediate `ScoringReplyModel` (its `scores` are "entry id => value") and decoding twice.
- **D4 — Rerank packs by count only.** Spec D7: "the window bounds each document, not their sum". `RerankProtocol::pack()` chunks the pool in candidate order by `maxItemsPerRequest` (100) and never sums tokens; `ScoringBatchPacker` stays System One's.
- **D5 — A document is cut to the budget's item share, not to what the actual query left.** Spec D7: "each cut to what is left of the window after the query". The budget already reserves the query's share (`min(10_000, 30 %)`) and 2,000 for framing, so each document gets `ScoringBudgetModel::itemTokens()`; cutting to the query's actual length would make a document's text depend on the profile's length, for no gain (the smallest reranker window, 4,096, leaves 868 tokens a document; the longest capped line is 773 tokens in three-byte characters). Cohere documents that a query may take up to half the window; 30 % stays below that.
- **D6 — The query is the question, the guidance and the profile; no favourites.** Spec D7 names those three. Order and fitting mirror `ScoringStateFactory`: the question first (fixed), the guidance fitted beside an empty profile so the profile's label still fits, then the profile fitted to what is left. Both texts are `mb_scrub`bed: the query is JSON-encoded with `JSON_THROW_ON_ERROR`.
- **D7 — A result whose index names no document is ignored; a repeated index spoils the reply.** Spec D10 names "missing or repeated". A repeated index makes `RerankReplyDecoder` return no scores, which `ScoreParser` refuses (unusable, retried). An index outside the request (or not an integer, or a result without a numeric `relevance_score`) is skipped; if that leaves an article without a score, the parser refuses the reply on the missing id. A value outside [0,1] passes the decoder and is refused by `ScoreParser` (raw logits from a local server, spec D10).
- **D8 — Usage:** `usage.total_tokens` becomes the call's prompt tokens (0 when absent or not a non-negative integer: `ProviderCallUsageModel` counts are ints), completion, reasoning and cached tokens are 0, cost is `usage.cost` through `ReportedCost`; no `usage` object at all is a null usage. Cohere bills `search_units` and reports no tokens; the run's cost is what matters (spike finding 6).
- **D9 — Names that fit both families (Task 1).** `ScoringBudgetModel::$stateTokens` → `$readerTokens` (System One's state, Rerank's query), `Support/ProbabilityScore` → `Support/ScaledScore` (a reranker's relevance is no probability), and `ScoreParser`'s wording follows. Behaviour unchanged; spec D6 named the old ones.
- **D10 — Score semantics need no change downstream; the hint carries them.** Read end to end: `ScoreParser` accepts values in [0,1] and scales them ×1000 (`ScaledScore`); `RecommendationWinnerRanker` sorts one run's pooled winners by that score (spike finding 4: relevance is comparable across batches of one run); `RecommendationRunFinalizer` stores it as `RecommendationItem::$score`; the for-you feed (`RecommendationItemRepository::listForYou`) orders by newest run, then position, and dedupes an entry to its newest run, so no score is ever compared across runs; no threshold or cut-off reads a score; the reader UI shows `score / 10` ("Score: 87") only with "show score and reasons" on. A reranker's score therefore needs nothing a decision model's does not; the picker's hint says it only ranks within a run (spec D9).
- **D11 — The scoring hint names only the families the provider lists.** Spec D9 states both halves; PR 2's D20 shows the hint only while "Scoring model" is picked. TypeSafe direct lists no reranker, so its reader is not told about one: the hint is the general sentence plus one sentence per family present in the model list. The keys move: `settings.ai.modelKind.scoringHint` keeps only the general sentence, `settings.ai.modelFamilyHint.{decision,reranker}` hold the halves.
- **D12 — A switch says what changed: two messages.** Carry-forward (PR 1 item 4, PR 2 D16): `ENGINE_SWITCH` ("a different recommendation engine") also fires, since PR 2, on a scoring-model switch, where it is wrong. `TickPhases::ENGINE_SWITCH` now names the kinds ("an LLM, a decision model and a reranker score articles differently") and fires on a kind or protocol switch; `TickPhases::SCORING_MODEL_SWITCH` fires on a scoring run whose connection holds another model of the same protocol ("its requests were sized for that model"). The kind/protocol check runs first.
- **D13 — The request is rebuilt per call, as System One's is.** Carry-forward (PR 1 item 3): `RerankRequestFactory::create()` runs in `open()` (for the log) and in `scoreMany()` (and on re-sends). Deterministic; the query fit is a binary search over at most a few thousand characters. Not memoised.
- **D14 — Rejected: a reranker-specific score display or score floor.** Out of scope; D10 found no consumer that needs one.
- **D15 — Real run on connection 8 without asking.** Lars approved real runs and dev-data changes for this series. Task 12 runs `cohere/rerank-4-fast` (32,768-token window) on connection 8 through the app's API and ends with connection 8 on `~typesafe/jev-latest`, active for user 2 (PR 2's D5: the bare `jev-latest` cannot be re-chosen on OpenRouter).
- **D16 — Known cost trait, measured not designed around.** Cohere bills a search unit per query with up to 100 documents, where a document plus the query longer than 500 tokens counts as several (Cohere pricing page). The dev profile is ~3,500 bytes (~880 tokens), so a Cohere request costs several units. Task 12 records `usage.search_units` and the cost per request; a design change (a shorter query for Cohere) is a follow-up if Lars wants one, not this PR.
- **Carry-forward items settled before this PR, unchanged here:** first-descriptor-wins (PR 2 D4; rerankers have no probe); the budget's home (PR 2 D7; `RerankProtocol::budget()` follows it); LM Studio and the query parameter (Task 12 checks again, read-only, if a server answers); bare `jev-latest` connections (PR 2 D5); windows ≤ 2,857 (PR 2 D19; Rerank's smallest is 4,096); Infection does not mutate git-renamed files (Task 1's renames carry no behaviour; their tests move with them).

<?php

declare(strict_types=1);

namespace App\Service\Recommendation\Scoring\Support;

use App\Service\Ai\Model\ProviderCallReceiptModel;
use App\Service\Ai\Model\ProviderCallUsageModel;
use App\Service\Ai\Support\ReportedCost;
use App\Service\Recommendation\Scoring\Model\ScoringReplyModel;

/** Never throws: a body that is not the documented shape decodes to no scores, which the parser rejects as unusable. */
final class RerankReplyDecoder
{
    /** @param list<int> $entryIds the request's entries, in the order its documents were sent */
    public static function decode(string $body, array $entryIds): ScoringReplyModel
    {
        $root = json_decode($body, true);
        $root = \is_array($root) ? $root : [];

        return new ScoringReplyModel(
            $body,
            self::scoresIn($root['results'] ?? null, $entryIds),
            new ProviderCallReceiptModel(
                self::textIn($root['id'] ?? null),
                self::textIn($root['model'] ?? null),
                self::usageIn($root['usage'] ?? null),
            ),
        );
    }

    /**
     * @param list<int> $entryIds
     *
     * @return array<int, float> by entry id; none at all when an index repeats
     */
    private static function scoresIn(mixed $results, array $entryIds): array
    {
        if (!\is_array($results)) {
            return [];
        }

        $scores = [];
        foreach ($results as $result) {
            $entryId = self::entryIdOf($result, $entryIds);
            $relevance = self::relevanceOf($result);
            if (null === $entryId || null === $relevance) {
                continue;
            }
            if (isset($scores[$entryId])) {
                return [];
            }
            $scores[$entryId] = $relevance;
        }

        return $scores;
    }

    /** @param list<int> $entryIds */
    private static function entryIdOf(mixed $result, array $entryIds): ?int
    {
        $index = \is_array($result) ? ($result['index'] ?? null) : null;

        return \is_int($index) ? ($entryIds[$index] ?? null) : null;
    }

    private static function relevanceOf(mixed $result): ?float
    {
        $relevance = \is_array($result) ? ($result['relevance_score'] ?? null) : null;

        return \is_float($relevance) || \is_int($relevance) ? (float) $relevance : null;
    }

    private static function usageIn(mixed $usage): ?ProviderCallUsageModel
    {
        if (!\is_array($usage)) {
            return null;
        }
        $totalTokens = $usage['total_tokens'] ?? null;

        return new ProviderCallUsageModel(
            promptTokens: \is_int($totalTokens) && $totalTokens >= 0 ? $totalTokens : 0,
            completionTokens: 0,
            reasoningTokens: 0,
            cachedTokens: 0,
            costNanoCredits: ReportedCost::nanoCreditsOf($usage['cost'] ?? null),
        );
    }

    private static function textIn(mixed $value): ?string
    {
        return \is_string($value) && '' !== $value ? $value : null;
    }

    private function __construct()
    {
    }
}

declare(strict_types=1);

namespace App\Service\Recommendation\Scoring\Factory;

use App\Service\Recommendation\Scoring\Model\ScoringReaderModel;
use App\Service\Recommendation\Scoring\Support\FittingPrefix;
use App\Service\Recommendation\Support\TokenEstimate;

/** The reader as one rerank query within a token budget: the question, then the guidance, then the profile. */
final readonly class RerankQueryFactory
{
    public const string QUESTION = 'Articles this reader would want to read, judged by the guidance and the reading '
        . 'profile below.';

    private const string GUIDANCE_LABEL = "\nGuidance: ";
    private const string PROFILE_LABEL = "\nProfile: ";

    public function create(ScoringReaderModel $reader, int $tokenBudget): string
    {
        $fits = static fn (string $query): bool => TokenEstimate::of($query) <= $tokenBudget;
        $opening = self::QUESTION . self::guidanceLine($reader->guidance, $fits) . self::PROFILE_LABEL;

        return $opening . FittingPrefix::of(
            mb_scrub($reader->profile, 'UTF-8'),
            static fn (string $prefix): bool => $fits($opening . $prefix),
        );
    }

    /**
     * Fitted beside an empty profile: the profile's label must still fit once the guidance has taken the budget.
     *
     * @param \Closure(string): bool $fits

    private static function guidanceLine(?string $guidance, \Closure $fits): string
    {
        if (null === $guidance) {
            return '';
        }

        return self::GUIDANCE_LABEL . FittingPrefix::of(
            mb_scrub($guidance, 'UTF-8'),
            static fn (string $prefix): bool
                => $fits(self::QUESTION . self::GUIDANCE_LABEL . $prefix . self::PROFILE_LABEL),
        );
    }
}

declare(strict_types=1);

namespace App\Service\Recommendation\Scoring\ScoringProtocol;

use App\Enum\ScoringProtocol;
use App\Service\Ai\Model\ProviderCredentialsModel;
use App\Service\Recommendation\Pool\Model\ArticleLineModel;
use App\Service\Recommendation\Scoring\Factory\RerankRequestFactory;
use App\Service\Recommendation\Scoring\Model\ScoringBudgetModel;
use App\Service\Recommendation\Scoring\Model\ScoringRequestModel;
use App\Service\Recommendation\Scoring\RerankClient\RerankClientInterface;
use Symfony\Component\DependencyInjection\Attribute\AsTaggedItem;

/** A reranker: the reader as the query, one document per article, each ranked by its relevance to the query. */
#[AsTaggedItem(index: ScoringProtocol::Rerank->value)]
final readonly class RerankProtocol implements ScoringProtocolInterface
{
    /** One Cohere search unit; the window bounds each document, not their sum. */
    public const int DOCUMENTS_PER_REQUEST = 100;

    public function __construct(
        private RerankRequestFactory $requestFactory,
        private RerankClientInterface $client,
    ) {
    }

    public function budget(int $contextWindowTokens): ScoringBudgetModel
    {
        return ScoringBudgetModel::forWindow($contextWindowTokens, self::DOCUMENTS_PER_REQUEST);
    }

    public function pack(ScoringBudgetModel $budget, array $candidates): array
    {
        return array_chunk(
            array_map(static fn (ArticleLineModel $candidate): int => $candidate->entryId, $candidates),
            $budget->maxItemsPerRequest,
        );
    }

    public function renderedRequest(ScoringRequestModel $request): string
    {
        return $this->requestFactory->create($request)->toRenderedRequest();
    }

    public function scoreMany(ProviderCredentialsModel $credentials, array $requests): array
    {
        return $this->client->rerankMany($credentials, array_map($this->requestFactory->create(...), $requests));
    }
}
