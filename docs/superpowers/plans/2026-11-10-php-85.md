# PHP 8.5 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every runtime the app runs on (Docker, CI, Strato CLI, Composer platform) moves to PHP 8.5 (#2148). As a
result, readability.php uses the native `Uri\WhatWg\Url` instead of the userland `rowbot/url`.

**Architecture:** The version is changed everywhere at once, with no compatibility window. The one new piece of logic
guards the Strato flip: with the Composer platform at 8.5, an 8.4 vhost would fatal on every request. So activation
first probes the live vhost's PHP version and refuses to flip below 8.5.

**Tech Stack:** PHP 8.5 (`php:8.5-fpm-alpine`, Homebrew `php` 8.5.12 locally), Composer, GitHub Actions
(`shivammathur/setup-php`), bash, shellcheck.

**Spec:** `docs/superpowers/specs/2026-11-10-php-85-design.md`

### Task 3: Vhost PHP guard script

**Files:**
- Create: `deploy/strato/check-vhost-php.sh`
- Create: `scripts/test/check-vhost-php.test.sh`
- Modify: `.github/workflows/ci.yml`, Scripts job. Add both files to the `shellcheck` line, and add a step
  `run: scripts/test/check-vhost-php.test.sh` after the `check-authorization-header` step, with a one-line comment.
- Modify: `.github/workflows/deploy-strato.yml:282`, so the step also copies
  `deploy/strato/check-vhost-php.sh "${RELEASE_DIR}/check-vhost-php.sh"`. Rename the step to
  "Add the activation scripts to the release".

**Interfaces:**
- Produces: `check-vhost-php.sh <public-dir> <base-url> <minimum-version-id>`.
  - Exit 0 when the vhost's `PHP_VERSION_ID` is at least the minimum.
  - Exit 1 with a message naming the vhost's version and the minimum.
  - Exit 1 when the probe cannot be fetched.
- Behaviour, in order:
  1. Write `<public-dir>/php-version-<random>.php`, containing `<?php echo PHP_VERSION_ID;`. Build the random part
     from `od -An -N8 -tx1 /dev/urandom | tr -d ' \n'`. No leading dot, because the mount's `.htaccess` denies
     dotfiles.
  2. Remove it in an `EXIT` trap.
  3. Fetch `<base-url>/php-version-<random>.php` with `curl -fsS --max-time 20`. Strip a trailing slash from
     `<base-url>`.
  4. Require the body to be all digits. Otherwise fail with "the vhost did not run the PHP probe" plus the first
     200 bytes of the body. This catches PHP served as text, and an HTML fallback page.
  5. Compare the number to the minimum.
  6. On refusal the message says: switch the vhost's PHP version in the Strato panel, then deploy again; `current`
     was not flipped.

- [ ] **Step 1: Failing test.** Follow the pattern of `scripts/test/check-authorization-header.test.sh`: a fake
  `curl` on `PATH` that records its arguments and answers from a responses file. Cases:
  - `80512` passes;
  - `80500` passes;
  - `80412` fails, and the message contains `8.4.12` and `8.5`;
  - a body `<?php echo PHP_VERSION_ID;` fails with "did not run the PHP probe";
  - a curl exit 22 fails;
  - the fetched URL is `<base-url>/php-version-*.php`, with a single slash even when `<base-url>` ends in `/`;
  - the probe file exists while curl runs (the fake curl checks with `ls <dir>/php-version-*.php`) and is gone
    afterwards, in both success and failure cases.

  Run `scripts/test/check-vhost-php.test.sh`. Expected: it fails because the script does not exist.
- [ ] **Step 2: Implement the script.** Format the version as `major.minor.patch` from the id: `80412` is `8.4.12`.
- [ ] **Step 3: Check it.** Run `scripts/test/check-vhost-php.test.sh`, which must pass, and
  `shellcheck deploy/strato/check-vhost-php.sh scripts/test/check-vhost-php.test.sh`, which must be clean.
