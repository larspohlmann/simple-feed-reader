# PHP 8.5 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every runtime the app runs on (Docker, CI, Strato CLI, Composer platform) moves to PHP 8.5 (#2148). As a
result, readability.php uses the native `Uri\WhatWg\Url` instead of the userland `rowbot/url`.

**Architecture:** The version is changed everywhere at once, with no compatibility window. The Strato vhost was
switched and checked by hand; there is no activation guard (dropped at Lars's request).

**Tech Stack:** PHP 8.5 (`php:8.5-fpm-alpine`, Homebrew `php` 8.5.12 locally), Composer, GitHub Actions
(`shivammathur/setup-php`), bash, shellcheck.

**Spec:** `docs/superpowers/specs/2026-11-10-php-85-design.md`

## Global Constraints

- Branch `feature/2148-php-85` (exists, off `develop`). Commits: `type(#2148): …`, no Claude attribution. Never
  push, checkout, reset or stash.
- New version strings are exactly:
  - `php:8.5-fpm-alpine`
  - `php-version: '8.5'`
  - `"php": ">=8.5"`
  - `config.platform.php: "8.5.0"`
  - `/opt/RZphp85/bin/php-cli`
  - minimum `PHP_VERSION_ID` `80500`
- Measured facts about the 8.4.22 host (dated measurements in the Strato README) stay as history. Only instructions,
  paths and current-state claims move to 8.5.
- Native PHP on this Mac: `php` is 8.5.12 with pcov. 8.4 is `/opt/homebrew/opt/php@8.4/bin/php`.
- Any native PHPUnit run sets `TEST_TOKEN`, because another session may share this checkout.
- Docker: rebuild only the `php` service (`docker compose build php && docker compose up -d --no-deps php worker`).
  Never `down -v`.
- Shell scripts: bash 3.2-safe like their siblings, `set -euo pipefail`, shellcheck-clean.
- Comments only where a reader would get the code wrong without them (CLAUDE.md).

### Task 1: Clear PHP 8.5 deprecations in src and tests

Measured with the full native suite on PHP 8.5.12 (`TEST_TOKEN=php85 php vendor/bin/paratest`): 1 failure, 46
deprecations, 1 risky test. They come from 9 sites, all first-party; nothing comes from `vendor`. The failure and
the risky test are both `GuardedImageProbeTest::testAMidBodyFailureIsUnavailableNotAnErrorException`: its error
handler turns the `imagedestroy()` deprecation in `tests/Support/PngImageFactory.php:20` into an `ErrorException`.

**Files and fixes:**
- `src/Service/Image/ImageResizer/GdImageResizer.php:30,31,49,50`, `tests/Service/Image/ImageResizer/GdImageResizerTest.php:29,91`
  and `tests/Support/PngImageFactory.php:20`: delete the `imagedestroy()` calls. It has had no effect since PHP 8.0.
- `src/Service/Mail/Transport/Pass/CurlSmtpTransport.php:44,67`: delete the `curl_close()` calls, for the same
  reason. If a `finally` block becomes empty, remove the `try/finally` too.
- `src/Service/Fetch/ConcurrentRequestEngine.php:245`: `$inFlight->detach($response)` becomes
  `$inFlight->offsetUnset($response)`.
- `src/Service/Scraper/ScrapeLayer/ClusterLayer.php:113,152`: `->contains($x)` becomes `->offsetExists($x)`.
  Use `isset($storage[$x])` only if it reads better and PHPStan accepts it.
- `src/Http/EntryPage.php:48` and `src/Service/Search/EntrySearch/IndexedEntrySearch.php:54`: "Using null as an
  array offset". Find the nullable key, and handle the null case explicitly the way the surrounding code intends (a
  guard or a typed default). Do not just cast to `''`.
- `src/Service/Fetch/Support/RetryAfterHeader.php:27`: `DATE_RFC7231` is deprecated. Use the literal HTTP-date
  format `'D, d M Y H:i:s \G\M\T'` in a named private const, and keep the parsing behaviour identical. The
  existing `RetryAfterHeaderTest` must stay green.
- `src/Doctrine/SqliteConnectionSetupDriver.php:58`: `PDO::sqliteCreateFunction()` becomes
  `Pdo\Sqlite::createFunction()`. First check what the native connection is. On 8.5, `new PDO('sqlite:…')` returns a
  plain `PDO`, and only `PDO::connect()` or `new Pdo\Sqlite` gives the subclass. If Doctrine's driver hands over a
  plain `PDO`, report it as NEEDS_CONTEXT with what you found, instead of forcing it.

- [ ] **Step 2: Fix each site** as listed. Each fix is behaviour-neutral. Where a site has no test that pins the

- [ ] **Step 3: Verify.** Rerun the full native suite: 0 failures, 0 deprecations, 0 risky. Also run the touched
