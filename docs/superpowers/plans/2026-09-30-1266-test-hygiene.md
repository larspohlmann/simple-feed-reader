## Decisions

- **D-1: `self::FLOOR`, not `EntryPruner::MIN_ENTRIES_PER_FEED`.** The constant is private (`src/Service/Retention/EntryPruner.php:22`: `    private const int MIN_ENTRIES_PER_FEED = 20;`), and this is a test-only PR. Keeping the test's own `FLOOR = 20` also means a changed floor fails the suite instead of every expectation silently following it.
- **D-2: `testCapIsPerFeedNotGlobal` uses three feeds under `CAP_ABOVE_THE_FLOOR` (22).** Feed A is one entry over the cap and fetched two days ago. Feed B is at the cap and older. Feed C is at the cap and newer. Only A loses an entry. The two ways a cap goes global each delete 23 instead of 1:
  - If the delete query is not scoped to the feed, B's entries fall past A's boundary.
  - If the ranking is not scoped to the feed, the boundary lands inside C, and all of A falls past it.

  The #1171 plan suggested two feeds of `CAP_ABOVE_THE_FLOOR - 1` entries each. That shape fails no single-edit break: `feedIdsOverCap()` groups by feed, and the ranking is per feed, so a global version needs both to change at once.
- **D-3: `testFeedAtOrUnderCapIsUntouched` holds one feed at the cap (22) and one just under it (21).** Both feeds sit above the floor. Two deletion checks cover it:
  - Clamping to the floor, which ignores the configured cap, deletes 3.
  - An effective cap one lower deletes 1.

  The old test (cap 3, three entries) passes both breaks, because the clamp raises the cap to 20.
- **D-4: The literal sweep covers every floor-derived number in `EntryPrunerTest`, including prose and names.** Counts become `self::FLOOR + n`. Guid ranges become `self::FLOOR + n - 1`. `testNeverDeletesAFeedsNewestTwentyEntries` becomes `testNeverDeletesAFeedsNewestEntriesWithinTheFloor`. `testAFeedOfTwentyOldEntriesLosesNone` becomes `testAFeedOfOldEntriesAtTheFloorLosesNone`. Docblocks that spell the numbers are cut to one line or deleted, where the assertion already says it. Only the plans under `docs/superpowers/plans/` name the two tests, and those are history, so they stay.
- **D-5: One `entryGuids(int $first, int $last)` helper.** The `array_map(static fn (int $index): string => "entry-{$index}", range(…))` expression occurs 7 times at `bf742411`, and D-2 would add an eighth. CLAUDE.md's DRY rule makes the third occurrence a refactor. The helper is `private static`: it reads no state.
- **D-6: The new name is `SubscriptionPositionAndLookupsTest`.** Its four tests cover `nextPositionForUser()` (two tests), `findForUserWithTags()` and `findForUserByTagId()`. The counts live in `SubscriptionEntryCountsTest` and `SubscriptionCountsByUserIdTest`. Nothing outside `docs/superpowers/plans/` (history) names the class. `bf742411:docs/superpowers/plans/2026-09-29-1171-comment-rules.md:58398` proposed this name.
- **D-7: `WorkerHeartbeat`'s writers are the three `RecommendationDriverKind`s.**
  - `WorkerHeartbeatRepository::touch()` is the only `INSERT INTO worker_heartbeat`. Its one caller is `WorkerPresence::mark()` (`src/Service/Recommendation/Run/WorkerPresence.php:32`: `        $this->heartbeats->touch($kind->heartbeatName(), $this->clock->now());`).
  - `mark()` has three callers:
    - `src/Service/Worker/WorkerRunSweep.php:54` and `:62`: `                $this->presence->mark($kind);`. The persistent worker reaches it through `AdvanceRecommendationRunsHandler.php:25` (`        $this->sweep->sweep(RecommendationDriverKind::PersistentWorker);`), and the drainer through `RecommendationDrainCommand.php:131` (`        while ($this->sweep->sweep(RecommendationDriverKind::OnDemandDrainer) > 0) {`).
    - `src/Service/Recommendation/Run/SweepStreamHeartbeat.php:70`: `        $this->presence->mark($this->sweepingAs);`.
    - `src/Service/Recommendation/Run/ForYouSweep.php:75`: `                $this->presence->mark(RecommendationDriverKind::CronSweep);`.
  - The key is `RecommendationDriverKind::heartbeatName()`: `'recommendation-sweep'`, `'recommendation-drain-sweep'` or `'recommendation-cron-sweep'`.
  - The worker process also schedules `RefreshDueFeeds` (`WorkerSchedule.php:38`), but no refresh code writes a heartbeat.

  The new reason: `'Liveness telemetry for the "For you" run drivers, one row per RecommendationDriverKind.'`
- **D-8: Both notes are deleted, not shortened.**
  - At `bf742411` the `OpmlImporterTest` note is at lines 101–103. The issue's `97-99` points at an older revision of the file. The `FeedLinkScannerTest.php:30` note is one line, not three.

  - The input under test is what the assertion pins. A `lang` attribute added to `'<html><body>not opml</body></html>'` would still be rejected as non-OPML, so no reader can break the test by following PhpStorm.
- **D-9: Commit types.** Every commit is `test(#1266): …` (test-only), except the plan copy, which is `docs(#1266): add plan`.
