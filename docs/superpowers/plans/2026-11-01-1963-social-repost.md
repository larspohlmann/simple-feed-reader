# Social repost (#1963) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repost / unrepost (Bluesky repost, Mastodon boost) the article's post and every reply in the comments panel, through a Repost menu on the counts row.

**Architecture:** A per-network `PostReposter` (tagged locator, like `PostLiker`) acts on a `SocialPostModel` that the existing `PostResolver`s now also fill with the viewer's repost (`existingRepostId`) and whether reposting is allowed (`canRepost`). `SocialReposts` orchestrates entry and reply reposts without storing anything — the network keeps the state, read back through a new `GET /api/entries/{id}/social/viewer` that replaces `GET /like` and answers `{isLiked, isReposted, canRepost}` from one resolve. Replies carry `isReposted`/`canRepost` in the comments payload. The frontend's counts row turns the repost count into a `RepostButtonComponent` (CDK popover menu on fine pointers, `ActionSheet` on coarse), shared by the article row and each reply row.

**Tech Stack:** Symfony 7.4 / PHP 8.4, PHPUnit 12, Angular 20 signals, Jest, Transloco.

**Spec:** issue #1963 and the umbrella #1962 (design grilled 2026-11-01).

## Global Constraints

- Same network only; acting account resolves exactly as for likes (`ActingAccountChooser` via `SocialPostFinder`).
- Article view only — no list-card action.
- New limiter `social_writes`: sliding window, **30 per 10 minutes** per user, used by every repost/unrepost (later slices reuse it). Likes keep `social_like`.
- Restricted actions are **disabled with a tooltip, never hidden**.
- Mastodon reblog/unreblog need scope **`write:statuses`**; missing → existing `409 social_token_scope_missing` (naming the scope). Settings hint lists `read`, `write:favourites`, `write:statuses`.
- No stored repost state (no table, no migration).
- HTTP status codes are `Response::HTTP_*` constants, in src and tests.
- Commit format `feat(#1963): …`.

## Rulings made while planning (record in the PR body)

1. **Viewer state endpoint.** Repost state is article-only, so it does not ride the list JSON (`EntryListRowSocial` unchanged). `GET /api/entries/{id}/like` becomes `GET /api/entries/{id}/social/viewer` → `{isLiked, isReposted, canRepost}`, still mirroring the stored like; slices 2/3 add `canReply`/`canQuote` there. Same `social_like_state` limiter.
2. **Repost menu now has one item** (Repost/Boost or Undo). Quote joins it in #1965. Two taps also guard a public action against a mis-tap.
3. **Scope badge skipped.** The umbrella made the "needs new scope" badge conditional on reliable detection; a probe call per account per Settings load is not worth it. The 409 toast plus the updated hint cover it.
4. **`PostReposter` parallels `PostLiker`** rather than generalising both into one "marker": this is the second occurrence, and replies/quotes (slices 2/3) are compose actions of a different shape.
5. **Mastodon `canRepost`** = visibility `public` or `unlisted`. Bluesky is always repostable.

```php
/** Reposts an entry's post or a reply in its thread; the network keeps the repost, so nothing is stored here. */
final readonly class SocialReposts
{
    public function __construct(
        private SocialPostFinder $posts,
        private PostReposting $reposting,
        private SocialCountsCache $countsCache,
        private CommentsLoader $comments,
    ) {
    }

    public function repost(User $user, Entry $entry): void
    {
        $this->repostIfNot($this->posts->find($user, $entry));
        $this->forgetCountsOf($entry);
    }

    public function unrepost(User $user, Entry $entry): void
    {
        $this->undoIfReposted($this->posts->find($user, $entry));
        $this->forgetCountsOf($entry);
    }

    public function repostReply(User $user, Entry $entry, string $address): void
    {
        $this->repostIfNot($this->posts->findReply($user, $entry, $address));
        $this->comments->forget($user, $entry);
    }

    public function unrepostReply(User $user, Entry $entry, string $address): void
    {
        $this->undoIfReposted($this->posts->findReply($user, $entry, $address));
        $this->comments->forget($user, $entry);
    }

    private function repostIfNot(SocialPostModel $post): void
    {
        if (null !== $post->existingRepostId) {
            return;
        }
        if (!$post->canRepost) {
            throw new SocialPostRefusedException('The author keeps this post from being reposted.');
        }
        $this->reposting->repost($post);
    }

    private function undoIfReposted(SocialPostModel $post): void
    {
        if (null !== $post->existingRepostId) {
            $this->reposting->unrepost($post->account, $post->existingRepostId);
        }
    }

    private function forgetCountsOf(Entry $entry): void
    {
        $post = SocialPostAddress::of($entry);
        if (null !== $post) {
            $this->countsCache->forget($post);
        }
    }
}
```
