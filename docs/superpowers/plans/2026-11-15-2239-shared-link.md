# Link cards as one `shared_link` row per URL (#2239) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each linked article is stored once, in `shared_link`, keyed by `UrlNormalizer::hash()` of its card URL.
Every card, reply card and quoted card references a row. The first card fills the preview, and a later post reuses
the row. The share sweep reads no page for a known post link, and the link reader refreshes the row from the page it
fetched. Trending reads the stored language and the stored hash.

**Architecture:**
- `App\Entity\SharedLink` + `SharedLinkRepository` hold the row.
- `Service/Ingestion/Language/PreviewLanguage` decides the language.
- `Service/Content/LinkCard/SharedLinkWriter` is the one writer, and `Service/Content/LinkCard/LinkArticleReader`
  refreshes.
- `Service/Content/Reader/Support/DeclaredPreview` parses a page's card and language once, for `PageCardReader` and
  the extractor.
- Three Doctrine migrations merge the existing cards: schema, merge and slim.
- A one-off `app:shared-links:fill-language` fills the existing rows' language.

**Tech Stack:** PHP 8.5, Symfony 8.1, Doctrine ORM 3 / DBAL 4, PHPUnit 12, Infection; Angular 20 for one line.

**Spec:** `docs/superpowers/specs/2026-11-15-2239-shared-link-design.md`, the binding authority. Read its Design,
Decisions D1–D17 and Research R1–R5 before Task 1.

## Global Constraints

- **Binding rulings (spec Intent, D2, D3, D7, D13):**
  - the first card fills a row's preview, and no writer rewrites it;
  - only `LinkArticleReader`, on an ok extraction, refreshes the preview and fills an unset language;
  - no page read for a known **post** link; a titled share's target and the "RE:" target keep their read;
  - no cleaned-link verification in the refresh;
  - a set language is never changed.
- **Out of scope (spec Non-goals, Optional scope):**
  - resolved-URL columns (#2236);
  - backup link lines or a schema version bump;
  - stored declared media;
  - the Mastodon card `language` field;
  - composer reuse;
  - a refresh throttle.
- **API:** the JSON of `/api/entries`, `/api/trending`, `/api/reader` and backups is unchanged for the same preview.
  No `Http/*Json` mapper changes its input type (D16).
- **Dev DB:** read only. Tests never touch MySQL dev. Measuring uses scratch databases named `feedreader_2239_*` only,
  created and dropped as root in the mysql container (spec R5). `feedreader` and `feedreader_2237_uncleaned` are never
  written.
- **House rules (CLAUDE.md):**
  - `final readonly` by default; entities and repositories `final`; one role per folder; queries only in
    `src/Repository`;
  - at most three parameters, and no boolean flags;
  - no comment unless a reader would get the code wrong;
  - every touched `src` file is PHPMD-clean: `rm -rf ~/.pdepend`, then
    `HOME=$(mktemp -d) vendor/bin/phpmd analyze <files> --no-progress`. No suppressions, no count-driven splits; if
    the commit hook denies new classes, report BLOCKED with its message;
  - no PHPStan ignores or docblocks to silence a finding, and no `tests/PhpStan` edits;
  - `Response::HTTP_*` for statuses;
  - `#[DataProvider]`, and matchers on `$this`;
  - the `Entry` field count reaches exactly 15. Add nothing else to `Entry`.
- **The dev Docker database lags the mapping from Task 4 to Task 11.** Tests build their schema from the mapping, so
  they are unaffected. Do not exercise the live dev app against the new code before Task 11's migrations exist.
- **Migrations:** platform-aware DDL as in `Version20261017160000`. Constraint and index names come from
  `doctrine:migrations:diff` run on each platform, then hand-merged. `isTransactional(): false`.
- **French and Spanish first-class** in every measurement.
- Commit format `type(#2239): lower-case imperative summary`, with no Claude attribution. Work on the main checkout,
  branch `feature/2239-shared-link`. Never push. Commands run in the foreground. No background jobs, no polling, no
  subagents.

## Review Focus

1. **First wins.** No path but `SharedLink::refresh()` writes a preview to an existing row. `linkFor()` on a known
   hash returns the stored row untouched, with a different title and a stated language. The merge keeps the oldest
   card (entry `created_at`, card before quote, then id).
2. **No read for a known post link.** Pin all of these in tests: a known post link costs no budget and no fetch, gets
   no posted-form check, and keeps post order. A titled target and the "RE:" target are still read.
3. **Referential safety.**
   - An entry purge never deletes a row another card uses.
   - Garbage collection deletes only rows with no card, no quote, and `created_at` before now − 1 day.
   - A snapshot reference becomes null.
   - A saved copy of a quote post keeps `quoted_shared_link_id`.
4. **Concurrency.** Two writers creating one URL never raise `UniqueConstraintViolationException`. A reused URL burns
   no auto-increment id.
5. **Trending identity.** For a row with a guessed language, `SharedArticles` gives the same language as develop's
   `CardLanguage::of()`. `TrendingStories` no longer depends on `UrlNormalizer`. A post's row key equals its link's
   stored `url_hash`.
6. **Migrations.** 0 cards unlinked after the merge. SQLite keeps the FTS5 triggers, because `entry` is never rebuilt.
   `doctrine:schema:validate` is green on both platforms after migrating from empty.
