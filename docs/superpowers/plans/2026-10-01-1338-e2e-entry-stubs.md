# E2e entry stubs through one typed builder (#1338) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Playwright spec builds its entry stubs with the contract-true `entryWire()`, and CI type-checks `frontend/e2e/`, so a stub that drifts from `EntryDto` fails the gate instead of the weekly rot run.

**Architecture:** `e2e/support/reader.ts` already owns `entryWire()` (typed `EntryDto`) and `readerFailedJson()` (#592). Add one sibling, `entryDetailJson()`, for the `GET /api/entries/{id}` body. Migrate the 19 specs that hand-roll entries as untyped literals. Add `tsconfig.e2e.json` and a `typecheck:e2e` script to `check:static`, which CI already runs.

**Tech Stack:** Playwright, TypeScript 5, Angular 20 frontend.

**Spec:** Issue #1338. Root cause: #1326 made the reader template read `e.categories.length`. `EntryJson::commonFields` always sends `categories`; the hand-rolled stubs omit it, so the template throws and `.content` never renders.

## Global Constraints

- Behaviour-preserving: a migrated stub keeps every value its hand-rolled version had that differs from `entryWire()`'s default (`title`, `url`, `summary`, `excerpt`, `source`, `subscriptionId`, dates, flags, image fields, `savedSearches`). Only fields the old literal lacked take the builder's defaults.
- No new per-spec builder of a full entry object; a spec may keep a small local function that calls `entryWire()` with its overrides.
- Detail bodies: `json: entryDetailJson(entry, html)`, never `{ entry: { ...entry, contentHtml } }`.
- `tsconfig.e2e.json` sets `noPropertyAccessFromIndexSignature: false`: `process.env.X` is the idiom in 29 test files, and the flag guards app models, not environment reads.
- Prettier (100 columns) and ESLint stay clean: `docker compose exec -T frontend npm run check:static`.
- Scratch specs `e2e/zz-*` are deleted, never committed.

### Task 1: Support helper and the e2e type check

**Files:**
- Modify: `frontend/e2e/support/reader.ts` (add `entryDetailJson`)
- Create: `frontend/tsconfig.e2e.json`
- Modify: `frontend/package.json` (`typecheck:e2e`, chained into `check:static`)
- Modify: `frontend/e2e/article-audio-redirect.spec.ts` (TS7030 in `audioOrigin`'s request handler: every path returns)

- [ ] **Step 1:** Add to `e2e/support/reader.ts`:

```ts
/** A `GET /api/entries/{id}` body: the list entry plus its full article (#1100). */
export function entryDetailJson(entry: EntryDto, contentHtml: string): { entry: EntryDetailDto } {
  return { entry: { ...entry, contentHtml } };
}
```

- [ ] **Step 2:** Create `frontend/tsconfig.e2e.json`:

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "outDir": "./out-tsc/e2e",
    "types": ["node"],
    "noPropertyAccessFromIndexSignature": false
  },
  "include": ["e2e/**/*.ts", "playwright.config.ts"]
}
```

- [ ] **Step 3:** In `package.json`, add `"typecheck:e2e": "tsc -p tsconfig.e2e.json --noEmit"` and append `&& npm run typecheck:e2e` to `check:static`.
- [ ] **Step 4:** Run `docker compose exec -T frontend npm run typecheck:e2e`. Expected: errors only in the hand-rolled specs Task 2 migrates (`magazine-kicker-one-line`), none from env access, none in `article-audio-redirect` once Step 1's sibling fix lands.
