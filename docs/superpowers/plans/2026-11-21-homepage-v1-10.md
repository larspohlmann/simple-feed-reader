# Homepage, README and feature list for v1.10.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The homepage, `README.md` and `docs/features.md` describe v1.10.0, with every screenshot and the phone tour retaken on the current UI.

**Architecture:** Three hand-written texts are edited in place; nothing is generated from another. The screenshot scripts in `frontend/scripts/screenshots/` gain the setups and shots the new sections need, then the whole set and the tour are retaken against the dev stack. A Node test pins what the page and the gallery promise (files exist, metadata agrees, scenes match).

**Tech Stack:** Static HTML/CSS (`docs/homepage`), Markdown, Node 22 `node:test`, Playwright (the one `frontend/npm ci` installs), `cwebp`, `ffmpeg`.

**Spec:** `docs/superpowers/specs/2026-11-21-homepage-v1-10-design.md`

## Global Constraints

- No change to the app (`backend/src`, `frontend/src`). A bug a shot reveals gets an issue; a trivial one its own commit.
- The page stays one static file with no build step; tokens, type and section pattern as they are. New sections reuse `.split`, `.split.flip`, `.grid`, `.card`, `.shot`, `.zoom`.
- Homepage voice: impersonal and descriptive, no "you", no superlatives. `README.md` and `docs/features.md` keep "you".
- Every sentence added is checked against the running app or the code before it lands (sources in Task 2).
- No screenshot shows a real person's notifications, the instance's proxy host, or a post unfit for a public page. Look at every retaken file before committing it.
- Every setup script borrows and gives back; the demo account (`jamie.park@example.com`) ends as it started: 19 subscriptions, no social account.
- Never clear or reset the dev database. Scripts run from this checkout against `http://localhost:4200`.
- Credentials live only in `frontend/.env.screenshots` (gitignored), written by Lars. No script prints one; no step reads the file's values.
- The PR merges directly before v1.10.0 is cut: a merge touching `docs/homepage/` or `docs/screenshots/` deploys the page at once.
- Commits: `type(#2452): …`, no attribution lines.

## Review Focus

- **Trending with too few stories**: the shot or the tour records a near-empty list. Expected: the setup refuses to report ready below its floor (Task 3).
- **A setup aborted half-way**: borrowed feeds or a connected account stay on the demo account. Expected: every `teardown` is safe to run twice and from any state (Task 3).
- **A phone at 375 px**: the two new `split` sections must stack with no horizontal scroll, in both themes (Task 4).
- **Metadata drift**: the description lives in four tags; a share preview shows the old one if one is missed. Expected: the test fails (Task 1).
- **A tour recorded for one theme only**: the scene list carries start times for both; a missing `data-dark` jumps the video to 0. Expected: the test fails (Task 1, Task 5).
