# RSS Items Only Where the Spec Puts Them — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An RSS 2.0 entry is a core `<item>` that is a child of the core `<channel>`, which is itself a child of the root. An RSS 1.0 entry is an RSS 1.0 `<item>` that is a child of `rdf:RDF`. An `<item>` anywhere else is never an entry.

**Architecture:** `FeedFormatParserInterface::isEntry(\DOMElement $element, int $depth)` becomes `isEntry(\DOMElement $element, \DOMNode $parent)`. `StreamedFeedDocument` already holds the skeleton node the element would be placed under (`$openNode`) and passes it in. A depth cannot say "a child of the channel": `<rss><x:meta><item>` sits at depth 2 too. A parent can, and with it every parser states its spec rule directly.
- New `XmlHelper::isRoot(\DOMNode $node): bool` (`$node->parentNode instanceof \DOMDocument`), shared by Atom, RSS 1.0 and RSS 2.0.
- Atom: `isRoot($parent) && isElement($element, 'entry', ns)`. This is the same rule as `$depth === 1`.
- RSS 1.0: `isRoot($parent) && isElement($element, 'item', RSS1_NS)`.
- RSS 2.0: the parent's parent is the root, and with `CoreElement::inOwnNamespace($root)`, `isCore($parent, 'channel') && isCore($element, 'item')`.

**Measured before planning:** 235 dev-database feeds. All 7255 RSS 2.0 items sit at `rss/channel`, in no namespace. All 75 RSS 1.0 items sit at `rdf:RDF`. #1452 pinned `testAnItemInsideAnExtensionElementOfTheChannelIsStillAnEntry` only to preserve the pre-streaming `getElementsByTagName('item')` reach. This issue reverses that pin deliberately.

**Spec:** GitHub issue #1491.
