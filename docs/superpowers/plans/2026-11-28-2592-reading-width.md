# Article Width Preference Implementation Plan (#2592)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-account preference that sets how wide the article column runs: `standard` (today's 720px, the default), `wide` (960px) or `full` (the whole reader pane, side padding kept).

**Architecture:** A copy of the handedness preference (#2203), end to end: an `App\Enum\ReadingWidth` stored on `ReadingSettings`, patched through `PATCH /api/me/preferences`, returned by `MeJson`, carried by the backup; on the SPA a `CachedAccountChoice<'readingWidth'>` service, a segmented choice in Settings → Preferences, and the article page reading it as a `data-reading-width` attribute that picks the `max-width`.

**Tech Stack:** Symfony 8.1 / Doctrine (PHP 8.5), Angular 20 signals, SCSS, Transloco.

**Spec:** Issue #2592 and the design agreed in the session: three steps, `standard` default, `wide` = 960px, `full` keeps the article's existing inline padding, stored per account.

## Global Constraints

- Wire values: `standard`, `wide`, `full`. Default `standard`. JSON field `readingWidth`.
- `standard` renders exactly as today: `max-width: 720px`.
- `wide` = `960px`. `full` = no max-width; the article's `padding-inline: var(--space-4)` stays.
- Column `user_reading_settings.reading_width VARCHAR(8) DEFAULT 'standard' NOT NULL`.
- localStorage paint-cache key: `sfr.readingWidth`.
- The link reader (`?link=`) is an article view and uses the same `app-article-page`, so it follows the setting with no extra work — verify, don't special-case.
- Copy (key prefix `settings.`):

  | key | en | de | fr | es |
  |---|---|---|---|---|
  | `readingWidth` | Article width | Artikelbreite | Largeur des articles | Ancho de los artículos |
  | `readingWidthHint` | How wide an article runs on a large screen. | Wie breit ein Artikel auf einem großen Bildschirm läuft. | La largeur d'un article sur un grand écran. | El ancho de un artículo en una pantalla grande. |
  | `readingWidthSaveFailed` | The article width could not be saved to your account. | Die Artikelbreite konnte nicht in deinem Konto gespeichert werden. | La largeur des articles n'a pas pu être enregistrée dans votre compte. | No se pudo guardar el ancho de los artículos en tu cuenta. |
  | `readingWidthOption.standard` | Standard | Standard | Standard | Estándar |
  | `readingWidthOption.wide` | Wide | Breit | Large | Ancho |
  | `readingWidthOption.full` | Full width | Volle Breite | Pleine largeur | Ancho completo |

## Review Focus

1. A backup file with no `readingWidth`, or an unknown one, restores `standard` — `AccountLineTest`.
2. `PATCH {"readingWidth":"huge"}` is a 422 and changes nothing — `ReaderPreferencesControllerTest` invalid-body provider.
3. A logout resets the cached width so the next account doesn't inherit it — covered by `CachedAccountChoice.reset()`; the service spec asserts it.
4. Cinema mode (widened video, #1479) must still widen at `wide` and not shrink at `full`: its `--cinema-width: max(100%, …)` already floors at the column — check it on the live render.
5. Phone / narrow pane: every option looks identical to today when the pane is narrower than 720px — check on the live render at mobile width.
