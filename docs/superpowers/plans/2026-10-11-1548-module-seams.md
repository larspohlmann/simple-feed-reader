# #1548 Module seams: Share, LinkCard, Bluesky, one owner for a post's provisional share

**Goal:** the Ingest / Share / LinkCard / Bluesky / Completion modules depend on each other in the order the concepts
come: deciding what an entry shares comes before building its cards, Bluesky owns its own identity, and one class
decides a Bluesky post's provisional share.

## Rulings

- **The classifier asks Share's own interface, not Bluesky.** The issue moves `AtPostUri` into Bluesky *and* the
  "provisional link until the AppView answers" rule into `EntryShareClassifier` (Share). Share importing Bluesky would
  close Share → Bluesky → Share, so Share owns `PendingEmbed/PendingEmbedInterface::awaitsEmbed(Entry)` and Bluesky
  implements it (`BlueskyPendingEmbed`, `architecture.md` §9 inversion). The queue asks the same interface, so the
  AT-guid test has one caller per question.
- **The provisional link wins only over "none"**, as before: a Bluesky post the classifier calls a link or a media
  share keeps that verdict; one it calls none (including the over-long-prose case, hence "ahead of the prose check")
  becomes `Share::link(null)`.
- **The queue keeps the body-linking step**, renamed `linkBareUrls()`; turning it into its own service is #1546/#1545
  territory.
- **`TrailingUrl` moves beside `QuoteLine`** (`LinkCard/Support`): a namespace change; Bluesky already depends on
  LinkCard. Merging the two is left out.
- `BlueskyEntryRule` moves to the Bluesky root (a foreign interface's implementation stays in its own module, §10).
  Its tag still comes from `_instanceof`; it now sorts first, and Reddit/VideoPage `supports()` never match an AT post
  (bsky.app URLs), so first-match order changes nothing — the wiring test pins it.
