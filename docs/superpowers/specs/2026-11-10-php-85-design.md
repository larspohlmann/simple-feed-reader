# PHP 8.5 (#2148)

## Problem

On PHP 8.4, readability.php resolves every `href`, `src`, `srcset` and `poster` through `rowbot/url`, a WHATWG
parser written in plain PHP. On media-heavy pages that is 80–95% of readability's time (TechCrunch: 294 ms per pass
with `fixRelativeURLs`, 10 ms without). On PHP 8.5 the library uses the native `Uri\WhatWg\Url` by itself.

## Decision

Move every runtime the app runs on to PHP 8.5 at once: Docker (dev and prod), CI, the Strato CLI and the Composer
platform. There is no compatibility window: the platform becomes `>=8.5`, so the lock may use 8.5-only releases, and
Composer's platform check refuses an older runtime.

Step 0 of the issue (a throwaway 8.5 image benchmark before the change) is skipped at Lars's request. The before/after
benchmark is deferred and will be measured together with later issues in the series (#2158).

## Changes

| Area | Change |
|---|---|
| `docker/php/Dockerfile` | `php:8.5-fpm-alpine` in both stages; drop `opcache` from `install-php-extensions`, since 8.5 builds it in. |
| CI | `php-version: '8.5'` in `.github/actions/setup-backend/action.yml` (and its description), `catalog-rot-check.yml`, `deploy-strato.yml`, `e2e-rot-check.yml` (and its 8.4 comment). |
| `backend/composer.json` | `"php": ">=8.5"`, `config.platform.php: "8.5.0"`, then refresh the lock (`composer update --lock`; re-resolve only if the platform change requires it). |
| Strato activation | `PHP=/opt/RZphp85/bin/php-cli` in `deploy/strato/activate-release.sh`. |
| Paths and docs | `/opt/RZphp84` → `/opt/RZphp85`, and the stated versions, in `deploy/strato/.env.local.example`, `deploy/strato/README.md`, `backend/.env`, `docs/for-you-scheduling.md`, `docs/local-docker.md`, `CLAUDE.md`. Also the `DetachedConsoleCommandLineTest` fixture. Measured facts about the 8.4.22 host stay as history where they describe a measurement. Only instructions and current-state claims move. |

### No vhost guard

With the platform at 8.5, Composer's `vendor/composer/platform_check.php` makes every request fatal on an 8.4 vhost.
A probe in `activate-release.sh` was planned and dropped at Lars's request: the vhost is switched once, so it was
checked by hand instead (2026-11-10: the vhost answers `x-powered-by: PHP/8.5.12`, and `/opt/RZphp85/bin/php-cli` is
8.5.12 with every required extension). The README's "Upgrading the PHP version" note keeps the order for next time.

## Verification

- Both test legs: native SQLite on 8.5, and MySQL in the rebuilt 8.5 Docker image.
- `composer check` and `composer md` on 8.5.
- No new deprecations in the dev log or test output.
- Run phpmd 3.0 over a probe with 8.5 syntax: `clone($object, [...])` and `|>`. This is the open point carried over
  from #2153.
- The Docker stack comes up on the new image, and a reader view of a media-heavy article loads.
- `activate-release.sh` passes `shellcheck` and `bash -n`.
