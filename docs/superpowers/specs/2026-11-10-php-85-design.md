# PHP 8.5 (#2148)

## Problem

On PHP 8.4, readability.php resolves every `href`, `src`, `srcset` and `poster` through `rowbot/url`, a WHATWG
parser written in plain PHP. On media-heavy pages that is 80–95% of readability's time (TechCrunch: 294 ms per pass
with `fixRelativeURLs`, 10 ms without). On PHP 8.5 the library uses the native `Uri\WhatWg\Url` by itself.

## Decision

Move every runtime the app runs on to PHP 8.5 at once: Docker (dev and prod), CI, the Strato CLI and the Composer
platform. There is no compatibility window: the platform becomes `>=8.5`, so the lock may use 8.5-only releases, and
Composer's platform check refuses an older runtime.

Step 0 of the issue (a throwaway 8.5 image benchmark before the change) is skipped at Lars's request. The before/after
benchmark is deferred and will be measured together with later issues in the series (#2158).

### Vhost guard in `activate-release.sh`

With the platform at 8.5, Composer's `vendor/composer/platform_check.php` makes every request fatal on an 8.4 vhost,
so the live site would die at the flip. The vhost's PHP version is a Strato panel setting that the shell cannot read.

Before the flip, while `current` still serves the previous release, the script does the following:

1. Write a one-line probe, `php-version-<random>.php` (`<?php echo PHP_VERSION_ID;`), into `${ROOT}/current/public/`.
   The name has no leading dot, because the mount's `.htaccess` denies dotfiles.
2. Fetch it with `curl` from `DEFAULT_URI`, which it reads from `shared/.env.local`.
3. Delete the probe in a `trap`.
4. `die` unless the answer is at least `80500`.

Before the guard, the script requires `DEFAULT_URI` to be set, because it is the URL the probe needs. On a first
deploy there is no `current` yet: the guard is skipped with a printed note, and the one-time setup in the README
already tells the operator to set the vhost version.

The order for Lars is to switch the vhost to 8.5 in the panel first. The old 8.4-compatible release runs on 8.5, so
nothing breaks in between. Then deploy. The guard turns a forgotten step into a refused deploy instead of a dead
site.

## Verification

- Both test legs: native SQLite on 8.5, and MySQL in the rebuilt 8.5 Docker image.
- `composer check` and `composer md` on 8.5.
- No new deprecations in the dev log or test output.
- Run phpmd 3.0 over a probe with 8.5 syntax: `clone($object, [...])` and `|>`. This is the open point carried over
  from #2153.
- The Docker stack comes up on the new image, and a reader view of a media-heavy article loads.
- `activate-release.sh` passes `shellcheck` and `bash -n`. The guard is exercised locally against a stub URL that
  answers 80412, which is refused, and 80512, which passes.
